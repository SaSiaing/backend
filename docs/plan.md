# 가족 가계부 v1 — 작업 순서

3명 / 4주 / Go · Echo · PostgreSQL · sqlc / Flutter

리포는 둘로 나뉩니다 — [SaSiaing/backend](https://github.com/SaSiaing/backend) · [SaSiaing/app](https://github.com/SaSiaing/app).
이슈와 마일스톤은 **backend 리포에 모읍니다** (GitHub 마일스톤은 리포 단위라 나누면 두 벌이 됩니다).

마일스톤은 **무엇을 언제 만들었는지 기록하는 묶음**입니다. 달성 판정이나 통과 기준은 두지 않습니다.
다만 순서에는 근거가 있어서, 그건 아래에 남깁니다.

## 순서의 근거

제품 우선순위는 ① 내역 입력 ② 집계 ③ 가계 공유 ④ 목록·수정 입니다.
원래 이슈 목록은 기술 단계(인증 → 가계·멤버 → 내역 → 집계) 순이라 두 곳이 어긋나 있었습니다.

- **초대(`#18` `#19`)를 W2 → W3으로.** 순위 3위가 1·2위보다 앞에 있었습니다.
  그리고 텅 빈 앱에 가족을 초대하면 한 번 열고 안 옵니다. 보여줄 게 생긴 다음에 부릅니다.
- **집계 안에서 `#28` → `#29` → `#27`.** 사람별(`#27`)은 가족이 들어와야 값이 의미를 가집니다.
  혼자면 자기 이름 하나에 100%만 찍힙니다. 카테고리별은 며칠치로도 값이 나옵니다.
- **`#12`(GCP OAuth)를 W2 → W1로.** 코드 의존성이 없고 3명 SHA-1을 모아야 합니다.
  W2 첫날에 시작하면 그 주 인증 작업이 통째로 밀립니다.
- **실사용 입력을 W2 말부터.** 원래 W4 마지막 이슈였는데, 그러면 데이터가 며칠치도 안 쌓입니다.
  W2 말에 인증·등록·목록이 되므로 그날부터 각자 자기 지출을 넣습니다.

## M1 뼈대 (W1)

리포·개발환경·배포 파이프라인·Go/Flutter 뼈대. OAuth 클라이언트 발급까지.

`#02` `#01` `#03` `#08` `#12` / `#04` `#05` `#06` `#07` / `#09` `#10` `#11`

`#08`(배포)이 이틀 이상 막히면 Fly.io로 전환합니다. Cloud Run 설정에 매몰되지 않기.

## M2 입력 (W2)

인증, 가계 생성, 내역 등록·목록·삭제, 입력 화면. **여기서부터 실제로 지출을 기록하기 시작합니다.**

`#13` `#14` `#16` `#17` `#20` `#21` `#22` `#23a` `#37` / `#15` `#24` `#25` `#26a`

인증이 막히면 이메일+비밀번호 임시 인증으로 우회하고 `#13` `#14` `#15`를 뒤로 미룹니다.
인증이 늦어도 입력은 시작할 수 있어야 합니다.

## M3 집계·공유 (W3)

카테고리별 → 월별 → 사람별 집계, 대시보드, 초대 코드, 내역 수정.

`#28` `#29` `#27` `#30` / `#18` `#19` / `#23b` `#26b` / `#34` `#35` `#36`

## M4 정착 (W4)

폴링 동기화, 로딩·에러·빈 상태 정리, 실사용에서 나온 마찰 제거.

`#31` `#32` `#33`

`#33`은 "실사용 테스트"가 아니라 **2주 쓰면서 걸린 것들을 이슈로 옮기는 작업**입니다.
실사용은 W2 말에 이미 시작했습니다. 이슈가 적은 건 그 마찰을 담을 자리를 비워둔 것입니다.

## 쪼갠 이슈

혼자 쓰는 동안은 지우고 다시 넣으면 됩니다. 낙관적 락은 둘이 같은 걸 만질 때 물건입니다.

| 원래 | 결과 | |
|---|---|---|
| `#23` | `#23a` DELETE (soft delete만) | M2 |
| | `#23b` PATCH + 낙관적 락 409 | M3 |
| `#26` | `#26a` 스와이프 삭제 + 확인 | M2 |
| | `#26b` 탭 → 수정, 409 충돌 안내 | M3 |

## 신규 이슈

방향성 문서에는 있는데 원래 이슈 목록에 없던 것들입니다.

| | | |
|---|---|---|
| `#34` | 월 시작일 설정 화면 | `month_start_day` 컬럼은 있는데 **바꿀 화면이 없습니다** |
| `#35` | 카테고리 사용 빈도순 정렬 | `sort_order`(수동)와 다른 물건. 10초 목표에 직결 |
| `#36` | 중립 카피·색상 가이드 | 원칙 2. 금지 목록이 없으면 자연히 랭킹이 됩니다 |
| `#37` | `make seed` | 시드 없이 `#29`(6개월 추이)를 검증할 방법이 없습니다 |

대시보드 상단 "이번 달 수입·지출·수지"는 별도 엔드포인트를 만들지 않고 `#29`의 현재 달 행을 씁니다.

## 라벨

`phase:0~6`은 만들지 않습니다 — 마일스톤을 제품 순서로 재배치한 지금 어긋난 채로 남습니다.

`area:be` `area:fe` `area:infra` `area:docs` `blocker` `good-first` `must-have` `v2`

`must-have`는 제품 우선순위 1~4 직결 표시입니다. `#21` `#24` `#27` `#28` `#29` `#30`.
